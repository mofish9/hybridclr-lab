# HybridCLR DHE opt4 provider overlay validation

## Scope

This record closes the Windows Player overlay gap found during the r7
cross-target continuation. `HybridCLRDhePlayerRunner` now reads every current
DLL, current MetaVersion, Base MetaVersion, interpreter-only DLL, and build
identity through `IDheRuntimeAssetProvider`. `DheStreamingAssetReader` remains
only the provider's embedded-resource fallback. The external provider overlay
continues to exclude `BaseMetaVersion/`, so a resource update cannot replace a
Base's immutable MetaVersion set.

The source change is commit `f72d6b6b9c37480fc0663b509e7f11dfeacfb6b3` on
`optimize/dhe-android-device-v8.13.0`. The added host regression check is
`dhe-runner-provider-overlay`.

## Real Player evidence

A Unity 2021.3.45f2 StandaloneWindows64 bootstrap Player was rebuilt from the
candidate source and then run against a resource-only staging directory. The
staging directory was generated by `resource-update` and
`stage-resource-update` from the Player's own Base identity and a changed
four-assembly current set.

## Remaining gates

This is a Windows runtime-consumption proof only. Android still lacks a real
device Player result and PSS/RSS/thermal evidence, and iOS still requires a
macOS/Xcode build, signing, device execution, and performance evidence. The
candidate must not be promoted to a production resource channel until those
target-specific gates pass.
